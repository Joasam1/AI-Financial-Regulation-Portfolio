# 12-Month Technical Roadmap

This roadmap translates the AI × Financial Regulation development pathway into GitHub evidence. Dates and sequencing may be refined as learning and research milestones develop.

## Phase 1 — Foundations
- Strengthen Python for data analysis and reproducible research.
- Consolidate statistics and machine-learning foundations.
- Maintain learning and experiment logs.
- Reproduce small baseline models before moving to more complex systems.

## Phase 2 — Supervisory Machine Learning
- Develop an early-warning modelling workflow.
- Establish transparent train/validation/test procedures.
- Compare interpretable baselines with tree-based models.
- Add calibration, error analysis, explainability and stability diagnostics.
- Document confidentiality-safe or synthetic/public-data demonstrations.

## Phase 3 — Deep Learning & Transformers
- Build conceptual and coding understanding of neural networks and transformers.
- Implement selected components rather than relying only on high-level APIs.
- Record experiments and failure cases.

## Phase 4 — Regulatory RAG
- Construct a public regulatory-document corpus.
- Establish retrieval baselines.
- Compare chunking, embedding and retrieval strategies.
- Evaluate retrieval quality, groundedness and citation faithfulness.

## Phase 5 — Agentic AI
- Develop controlled multi-step workflows for research/regulatory tasks.
- Introduce tool use, state management and provenance.
- Evaluate task success, error propagation, reliability and cost.

## Phase 6 — AI Risk & Model Validation
- Develop validation protocols for AI systems used in high-stakes contexts.
- Test robustness, consistency, explainability and failure modes.
- Connect technical evaluation to governance and model-risk questions.

## Phase 7 — AI × Financial Stability
- Conduct reproducible empirical or simulation-based research.
- Translate technical findings into carefully bounded supervisory implications.

## Phase 8 — Regulatory LLM Benchmark
- Define tasks and scoring criteria.
- Build a versioned benchmark dataset using permissible material.
- Establish model baselines.
- Report reproducible results, limitations and error taxonomies.

## Portfolio rule

No project is labelled complete solely because code exists. Completion requires documented methodology, reproducible execution, evaluation evidence, limitations and a clear statement of what the artifact does and does not demonstrate.
